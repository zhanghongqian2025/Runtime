# 目标模式提示词 · 持续开发

目标模式读的是**结构化目标**，不是随口一句话。运行时用 `parseGoal` 解析目标文本
（`packages/local-runtime-v2/src/application/agent/goal/parse.ts`），规则如下：

| 段落 | 识别的标签（中 / 英） | 含义 |
| --- | --- | --- |
| 目标 | `目标` `目的` `最终状态` / `objective` `goal` | 结束时必须为真的状态 |
| 验收 | `验收` `验收标准` `验证` `完成标准` / `acceptance` `verification` | 怎么算完成（**必填**） |
| 约束 | `约束` `保持` `不能退步` / `constraint` `constraints` | 什么不能退步 |
| 边界 | `边界` `范围` `只使用` `允许修改` / `boundary` `scope` | 允许改什么 |
| 停止 | `停止条件` `阻塞条件` `停止` / `stop condition` `stopping` | 什么时候停下来汇报 |

写法要求：

- 标签必须在**行首**，后接 `:` 或 `：`，标签本身不超过 12 个字符；
- 标签下面可以跟多行（不带标签的行算作上一段的续行），每行一个条目；
- **目标**和**验收**都齐全才算解析成功。缺任何一项，模型会**反过来问你**（`ask_user` 问卷），而不是替你猜。

token 预算不在文本里，在接口层：`POST /v1/sessions/{id}/goal` 带 `tokenBudget`，
控制台的目标面板里有「token 预算」输入框，CLI 用 `--token-budget`。

## 一、模板（照着改，用在任何仓库）

```
目标: <一句话说清结束时必须为真的状态；要能被下面的验收标准检查>

验收:
- <可执行的判定 1：最好写成一条能跑的命令或一条能看的产物>
- <可执行的判定 2>
- <可执行的判定 3>

约束:
- <不能退步的既有行为：公开契约、兼容性、已有测试>
- <安全红线：不碰密钥、不擅自提交/推送、不做破坏性操作>

边界:
- <允许修改的目录或文件>
- <明确不允许碰的部分>

停止条件:
- <缺少外部输入、缺权限、需要人来拍板>
- <连续 N 轮没有进展>
- <触及约束或边界>
```

设定方式（三选一，效果相同）：

```bash
# CLI
node packages/cli/dist/index.js goal set "$(cat goal.txt)" --session <id> --token-budget 200000

# HTTP
curl -X POST http://127.0.0.1:8787/v1/sessions/<id>/goal \
  -H 'content-type: application/json' \
  -d '{"text":"...","tokenBudget":200000}'

# 浏览器控制台
#   http://127.0.0.1:8787/?panel=goal  →  粘贴文本 →  设定目标
```

也可以在对话里直接说「设定目标：…」，模型会调 `create_goal`；解析不出验收标准时它会反问你。

## 二、本仓库实例（local-agent-runtime，持续开发用）

```
目标: 持续把这个开源 coding agent runtime 往前推进：每轮自动选一件最有价值、
可验证的事做完并留下证据，目标未达成就继续下一轮，直到下面的验收全部成立。

验收:
- pnpm verify 全绿（lint + 依赖方向 + typecheck + 全部单测 + build + 真传输检查 8/8）
- 每轮结束都有可复查的证据：测试输出、构建日志、提交号或运行截图
- 改动不破坏 docs/contracts.md 里的任何一条契约；破坏了就先改契约并说明理由
- 新行为有对应的单测；e2e 用例不联网
- 目标达成时提交终态判断（完成/受阻/暂停）并附证据，而不是把状态留在半路

约束:
- 仓库内不出现任何密钥；密钥只从环境变量读，配置文件只写变量名
- 不擅自 git commit / push / 打标签；提交前先问
- 不改动 packages/protocol 的公开契约形状，除非契约本身要改且已同步文档
- 不删除既有测试来让验证变绿
- 运行时只在本机 127.0.0.1 上监听，不做对外暴露
- 代码用英文标识符与英文注释；文档与提示词可中英双语

边界:
- 可改: packages/ 下各包、e2e/、scripts/、docs/、README.md
- 可改: packages/local-runtime/src/http/ui/（控制台页面）
- 只读不改: ~/.config/local-agent/ 下的配置与密钥文件（需要改时先问）
- 不碰: 用户工作区里与本仓库无关的文件

停止条件:
- 需要密钥、需要联网、需要一个我没有的权限或凭据
- 连续两轮没有可验证的进展（目标模式会自动暂停并汇报）
- 发现现有设计与规格冲突，改不动又没有把握：停下来说明冲突与两个选项
- 触及约束或边界，或 token 预算用尽
```

配套建议：

- **token 预算**：`200000` 起步；一轮大约消耗几千到几万 token，预算太小会过早暂停。
- **先跑一轮看看节奏**：目标模式下每轮结束会由**独立 verifier 子会话**判定是否达成，
  连续两轮无进展自动暂停并给出结构化阻塞报告（已试过的路径、证据、还缺什么）。
- **想清楚再动手**：目标模式会自动续跑，所以**边界和停止条件要写死**，
  否则它会一路做下去。
- **和计划模式搭配**：先 `plan enter` → 让模型出计划 → `plan review` 冻结审阅 →
  `plan approve` 通过后再开目标模式，避免它直接改代码。

## 三、目标模式到底做什么（读目标前先知道）

- 每轮结束后，**verifier 在独立子会话**里判定目标是否达成（它不能改目标）；
- 没达成就**自动续跑**下一轮，直到：达成 / 预算用尽 / 超过 50 轮 / 连续两轮无进展 /
  方向被判定为错（暂停并汇报）；
- 暂停时给出结构化阻塞报告：已试过的路径、证据、还需要什么；
- 目标状态：`active → completed | blocked | paused | cleared`，可随时手动改。

也就是说：目标模式不是「让它写完一份报告」，而是**让它自己判断要不要继续干**。
把验收标准写成可执行的命令，它才有判断的依据。
